# Reader v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Learn mode into a distill-style article (centered prose column, tiers vertical in flow, annotated math) with a refined dark theme, and upgrade the 2504 paper content to use the new math blocks.

**Architecture:** The app already ships each concept's page markdown as a string in `data.gen.ts` (`KE_DATA.pages: Record<string,string>`). We keep that contract: new fenced blocks (`annotated-eq`, `derivation`, `algorithm`, `figure`) are parsed **client-side** in a new `src/lib/contentBlocks.ts` (YAML payloads via the `yaml` npm package, bundled — no runtime network). `build_data.py` is untouched except that `_load_pages` already stem-keys extra files, which we use for `_notation.md` / `_closing.md`. Learn mode swaps the graph workspace for `<ArticleView>` + `<ProgressRail>`; Explore mode is untouched. All colors/typography move to CSS variables in `src/styles.css` (tokens block at top).

**Spec:** `docs/superpowers/specs/2026-07-16-reader-v2-design.md`. One deliberate deviation: block parsing lives in the app (`contentBlocks.ts`), not `build_data.py` — same one-way data flow, no schema change, testable in vitest. `katexcheck.mjs` still validates payload LaTeX at authoring time.

**Tech Stack:** React 18 + TypeScript + Vite, Zustand v5, KaTeX (strict), `yaml` (new dep), vitest + @testing-library/react, pytest for `build_data.py` (unchanged), Python http.server for preview.

- [ ] **Step 3:** Implement:

```ts
import { parse as parseYaml } from "yaml";

const BLOCK_TYPES = new Set(["annotated-eq", "derivation", "algorithm", "figure"]);
const FENCE = /^```([\w-]+)\n([\s\S]*?)\n```$/;

export function parseContent(markdown: string): ContentSegment[] {
  const out: ContentSegment[] = [];
  const pieces = markdown.split(/(^```[\w-]+\n[\s\S]*?\n```$)/m);
  for (const piece of pieces) {
    const m = piece.match(FENCE);
    if (!m || !BLOCK_TYPES.has(m[1])) {
      if (piece.trim()) pushMarkdown(out, piece);
      continue;
    }
    out.push(toBlock(m[1], m[2]));
  }
  return out.length ? out : [{ type: "markdown", markdown }];
}

function pushMarkdown(out: ContentSegment[], piece: string) {
  const last = out[out.length - 1];
  if (last?.type === "markdown") last.markdown += piece;
  else out.push({ type: "markdown", markdown: piece.trim() });
}

function toBlock(kind: string, body: string): ContentSegment {
  let data: Record<string, unknown>;
  try { data = parseYaml(body) as Record<string, unknown>; }
  catch (e) { throw new Error(`content-block: invalid YAML in ${kind}: ${String(e)}`); }
  // per-kind required-key validation, throwing "content-block: …" errors:
  // annotated-eq → latex (string) + terms (non-empty array of {tex, role 1-5, words})
  // derivation   → steps (non-empty array of {latex, why}); optional shape
  // algorithm    → lines (non-empty array of {code, intent}); optional title
  // figure       → id (string); optional caption, props
  /* implement the four validators explicitly; no `any` leaks past this function */
}
```

Write the four validators fully (explicit key checks + typed returns). Trim markdown segments' outer blank lines but preserve interior content exactly.
