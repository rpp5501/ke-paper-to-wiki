# Attack Threat Model

## TL;DR {#tldr}
The Attack Threat Model lays out exactly what an adversary is assumed to know and be able to do before launching a targeted attribute inference attack, forming the foundation on which the paper's Attack Methodology is built. It sits within the broader study of Disparate Privacy Vulnerability, following directly from the Attribute Inference Preliminaries that define the attack setting. By pinning down realistic adversary capabilities up front, the model lets later sections reason precisely about what makes an attack feasible and how strong a defense needs to be.

## Intuition {#intuition}
The core idea is to ask: what is the minimum, realistic set of powers an attacker needs to guess a sensitive attribute about someone from a machine learning model's behavior? Rather than imagining an all-knowing adversary, the model grounds itself in what publicly queryable models actually expose — predictions and confidence scores — plus information that is often public or guessable, like the range of possible attribute values. This realism matters because it determines whether the resulting privacy vulnerability is a genuine, practical concern rather than a contrived worst case, and it sets up a fair basis for comparing attacks and later measuring how well defenses hold up.

## Mechanics {#mechanics}
The threat model grants the adversary three capabilities: black-box query access to the target model (returning both the output label and confidence scores), full knowledge of the non-sensitive attributes, and knowledge of every possible value of the sensitive attribute along with any non-sensitive attributes treated as group attributes [§sec_3]. These are framed as realistic because most existing model inversion attacks assume at least this much; the paper contrasts itself with Yeom et al., Fredrikson et al., and CSMIA, which additionally require full non-sensitive attribute knowledge for the specific target record, and with LOMIA, which needs complete non-sensitive attribute information across the entire target dataset [§sec_3]. Notably, unlike prior work, this adversary does not need knowledge of the marginal priors (the relative frequencies of sensitive attribute values) and does not require an auxiliary dataset matching the target distribution — a requirement common to most attribute inference attacks other than CSMIA and LOMIA [§sec_3]. The assumption of complete knowledge of all possible non-sensitive attribute values is justified by the observation that publicly queryable ML models often reveal all possible values of query attributes, and this knowledge is what lets the adversary partition records into groups based on non-sensitive attributes when running the proposed targeted attacks [§sec_3]. Finally, the model is deliberately asymmetric across the paper's two use cases: when mounting attacks to measure real-world leakage, the adversary is given fewer capabilities to reflect practical constraints, whereas when evaluating the proposed defense, the adversary is granted greater capabilities so the defense is stress-tested rigorously [§sec_3].
