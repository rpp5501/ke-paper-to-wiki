# Backdoor Defense
## TL;DR {#tldr}
Backdoor Defense is the general problem of determining whether a trained classifier has been compromised by a Backdoor Attack (BA), and, if so, disarming it. This concept sits at the top of a family whose most concrete instance is MM-BD: Maximum-Margin Backdoor Detection, the specific statistical test this paper proposes as a solution. Backdoor Defense stands in direct contrast to Backdoor Attack: one side plants a hidden trigger-to-label mapping during training, the other side tries to catch it after training is done. This concept also builds on the Post-Training Detection Scenario, the constrained setting where the defender only gets to inspect a finished model — no training data, no clean reference classifiers, no control over how the model was produced.

## Intuition {#intuition}
Think of a backdoored classifier as a model that behaves normally on almost every input but flips to an attacker-chosen label whenever a secret pattern is present. A backdoor defense is like a building inspector who shows up after construction is finished, with no blueprints and no access to the construction crew, and has to decide whether a hidden trapdoor was built into the structure. The defender in this paper's scenario is exactly that inspector: handed only the finished classifier, expected to render a verdict without any privileged information about how it was trained or what it was trained on.

## Mechanics {#mechanics}
Defenses can act at different points in a model's lifecycle. One family operates during training, watching the poisoning process itself and sanitizing the training set when it spots something wrong — but this is useless to a downstream user who receives an already-trained model and never sees the training pipeline [§sec_2_2]. The scenario this paper targets is different: a post-training defender who must decide if a pre-trained classifier is backdoored while having no access to its training set and no clean classifier to compare against, which rules out training-stage defenses entirely [§sec_2_2].

Among existing post-training approaches, meta-learning methods train a large bank of shallow networks, some deliberately backdoored and some clean, extract features from them, and use those features to train a binary meta-classifier that labels new models as attacked or not [§sec_2_2]. This approach is brittle in two ways: it presupposes a pool of candidate backdoor pattern (BP) types and can fail outright if the attacker's actual BP type isn't represented in that pool, and it demands a relatively large clean sample set plus significant training time [§sec_2_2].

A second family, reverse-engineering-based defenses (REDs), tries to reconstruct the backdoor pattern for each candidate target class, hoping to recover the real trigger if an attack exists, then flags the model as attacked when a recovered pattern's statistics (such as the norm of an estimated mask) look abnormal [§sec_2_2]. REDs need direct involvement of the BP-embedding process to drive their estimation, so they inherit assumptions about what kind of BP they're looking for, typically also require an independently held clean dataset, and tend to break down when an attack only involves a small number of source classes — a gap some prior work closes only at steep computational cost [§sec_2_2].

Against this backdrop, the defense strategy introduced in this paper is deliberately assumption-light: it makes no assumption about the BP type and requires no clean legitimate samples at all, and it is built to handle backdoors with an arbitrary number of source classes efficiently, which is where prior class-pair or joint-estimation approaches struggle [§sec_2_2]. Detection is only the primary goal; a secondary goal once an attack is confirmed is mitigation, since a replacement clean classifier usually isn't available — prior work handles this by fine-tuning the flagged classifier on a fairly large clean sample set to unlearn the backdoor mapping, whereas this paper's own mitigation approach (detailed elsewhere in the work) uses very few clean samples and adjusts no original parameters via fine-tuning, and can also be layered on top of existing mitigation methods [§sec_2_2].
