# Projected Gradient Ascent
## TL;DR {#tldr}
Projected Gradient Ascent (PGA) is the optimization loop MM-BD uses inside its Estimation Step to search for the input that maximizes a target class's logit margin. It repeatedly climbs the objective's gradient and snaps the result back into a bounded, valid input region, producing the "Maximum Margin" statistic that the rest of the detector relies on.

## Intuition {#intuition}
Think of PGA as hill-climbing with a fence around the hill. At each step you move in the direction that most increases how confidently a candidate input would be classified as the putative target class, but every move is immediately pulled back inside the allowed region (e.g., valid pixel values) so the search never wanders into meaningless or out-of-domain territory. Because this procedure sits directly inside the Estimation Step of MM Optimization, its only job is to produce the best achievable margin value for a given class — it is the engine that turns an abstract "how easy is it to push samples toward this class?" question into a concrete number.

## Mechanics {#mechanics}
Within the Estimation step, for each putative target class the detector solves the margin-maximization problem via gradient ascent with projection onto the feasible input set, and this process is guaranteed to converge because the logit functions are continuous and the feasible set is compact [§sec_3_2]. As common practice, the search is repeated from multiple random initializations within the feasible set — for images, pixel values are drawn uniformly at random — and the best solution found across restarts is kept, which guards against the ascent settling into a poor local optimum [§sec_3_2]. A key structural property is that this optimization is independent of the backdoor pattern type and does not require any clean labeled samples from source classes, which is what lets the same PGA-driven estimation detect attacks regardless of the number or identity of source classes, unlike reverse-engineering defenses that presume an embedding function and rely on clean samples from all non-target classes [§sec_3_2]. More generally, this ascent-then-project loop is the standard "projected gradient" pattern: take a gradient step to increase the objective, then project the iterate back onto a feasible set (commonly an epsilon-ball around a starting point intersected with the valid input range, such as [0,1]^d for images) [S1]. In practice such loops run for a modest number of iterations (roughly 7–40 in the canonical adversarial-robustness literature) with a per-step size scaled to the budget divided by the iteration count, clipping after every step [S1][S3]. A useful contrast is the single-step relative of this method, the fast gradient sign method, which ascends using only the sign of the gradient in one shot rather than iterating and projecting repeatedly [S2]. What distinguishes MM-BD's use of this loop from classic adversarial-example search is purpose and objective: adversarial PGD maximizes a classification loss under an imperceptibility constraint to flip a label, whereas MM-BD's ascent maximizes a logit-margin objective to estimate a per-class statistic, with no requirement that the resulting point be imperceptible — only that it remain inside the declared projection set [S1][S4].

## The Math {#the-math}
The quantity PGA is applied to maximize, for a putative target class over the feasible input set, is the logit-margin objective below [eq_2]:

$$
\maximize_{{\bf x}\in{\mathcal X}} \quad g_c({\bf x}) - \max_{k\in{\mathcal Y}\setminus c} g_{k}({\bf x})
$$ [eq_2]

Here PGA is the mechanism that solves this maximization: it ascends the gradient of the margin $g_c({\bf x}) - \max_{k\neq c} g_k({\bf x})$ and projects each iterate back onto the compact feasible set ${\mathcal X}$, and the resulting optimal value becomes the estimated MM statistic for class $c$ that feeds the detection inference step's order-statistic p-value test [§sec_3_2].

## Go Deeper {#go-deeper}
- Madry et al., *Towards Deep Learning Models Resistant to Adversarial Attacks* — the canonical derivation of projected gradient ascent/descent as an inner maximization solved via iterative gradient steps plus projection onto an epsilon-ball intersected with the valid input domain, i.e. the general method MM-BD's estimation step instantiates. https://arxiv.org/abs/1706.06083
- Goodfellow, Shlens, Szegedy, *Explaining and Harnessing Adversarial Examples* — introduces the single-step gradient-sign ascent (FGSM) that PGD/PGA generalizes into a multi-step projected version, useful for contrasting with the iterative loop used here. https://arxiv.org/abs/1412.6572
- MadryLab PGD adversarial-training reference implementation — minimal, widely-used reference code showing the exact projected-gradient-ascent loop (step, clip to epsilon-ball, clip to valid pixel range) in practice. https://github.com/MadryLab/mnist_challenge
- Kolter & Madry, *Adversarial Robustness — Theory and Practice* — freely available tutorial notes walking through projected gradient methods, step-size/iteration choices, and how they differ from single-shot perturbation search. https://adversarial-ml-tutorial.org/
